## Native build boundary

`profile.py` extracts Git blobs into ignored owned build directories. It compiles unchanged `TKlongdouble.C`, `tempo2Util.C`, `TKlog.C`, and the verbatim prefix `global.C:1–64`, bytes `[0,2085)` (the exact byte endpoint is also computed and recorded). No timing wrappers or CVS function are needed or linked. Real TKlog defines its own controls, counters and storage.

The raw float128 header becomes `TKlongdouble.h`. Only the three-line A2 `config.h` is reused; its bytes are hashed. No A2 object/archive, initializer correction, instrumentation, clock table, ephemeris or timing-model implementation is linked. All actual included headers, GCC driver and `cc1plus`, compiler flags, preprocessed units, macro profile, GCC runtime libraries, executable and link map are recorded. System libSystem is identified by OS and link dependency; its dyld shared-cache image is not extracted or hashed. The loader, system linker and kernel are not reproducible-build artifacts.

`-O2 -std=gnu++11 -DHAVE_CONFIG_H`, GCC 16, C locale, no fast-math or reassociation flags. Binary32/binary64/native-long-double and int/long widths are exported. Binary128's 113-bit significand is both declared by the header and measured by halving an epsilon against volatile one. Overload `static_assert`s check both remainder entry points and the binary128-base/binary64-exponent `pow`. Binary128 values export 36 significant decimal digits plus their 16 little-endian bytes and verify round-trip equality/sign; binary64 exports 17 digits and 8 bytes. Nonfinite classes are exact; NaN payloads are not numerical goldens. This lossless exporter is separate from source `%Qg` display.

## Numeric headers and branches

`TKlongdouble.float128.h` has 11 C++ inline wrappers: `cos`, `sin`, `fabs`, `sqrt`, `asin`, `atan2`, `pow`, `exp`, `log10`, `log`, `tan` (lines 37–72). Every wrapper is exercised with zero/negative zero, finite/domain-boundary, infinity and NaN inputs. `pow(__float128,double)` converts its already-binary64 exponent to quadmath precision; no extra precision is manufactured. Header macros `cosl`, `sinl`, `floorl`, `fabsl`, `powl` dispatch to quadmath and are called explicitly. `LD_PI=M_PIq`, `LONGDOUBLE_ONE=1.0Q`, token-pasting `longdouble(a)=a##Q`, `FMT_LD="Q"`, `USE_BUILTIN_LONGDOUBLE`, `LONGDOUBLE_IS_FLOAT128`, and include guards are listed verbatim in the inventory. `__cplusplus` exposes std::string and inline wrappers; parse/printf declarations have C linkage. `TKlongdouble.ld.h` is entirely inactive in this profile. It unconditionally defines USE_BUILTIN_LONGDOUBLE; its built-in branch defines LONGDOUBLE_IS_IEEE754, typedef long double, ONE=1.0L. The other branch declares DDREAL/dd.h and its pow, but is unreachable without changing that header's selection. `longdouble(a)=a##L`, `LD_PI=M_PI` (double constant), and printf/fprintf/sprintf aliases are distinct from the selected backend. The `sun`/sunmath include and C versus C++ declaration branches are inventoried, not executed. ## Declared callers and copy projection

Each independent case is a new process. An action sequence shares one process and TKlog/displayMsg lifetime. Input actions and function membership are stored in `cases.json`; `probe.cc` supplies fixed capacities and seeded state. All strings are initialized and terminated; formatter/output buffers use 0x5a guard bytes. Numeric arguments come from controlled literal strings. Numeric conversion preconditions are asserted before calling source, including `trunc(x +/- 0.5)` **after source arithmetic rounding**. Finite operands with infinite divisor give quotient zero and are valid remainder calls; the subsequent zero-times-infinity yields NaN. Invalid quotient conversions never execute.

Copy callers allocate two disjoint value-initialized pulsars and explicitly zero all object bytes, with three initialized observations each and independent capacity-four parameter storage. This is declared synthetic caller state, not TEMPO2 initialization. Source and destination use distinct 10/70-based sentinels for every source-copied scalar/string, four jump and FD-jump slots, position/velocity, a retained acceleration, offset error, solar-wind value, jump flags/indexes and full parameter metadata. Unseeded fields/array tails are declared zero. Observation records seed timing, residual, frequency, pulse number, file/telescope and a flag; all remaining fields are declared zero.

Every pulsar field is projected by name/offset/size, before/source/after sparse byte representation, equality-to-source, retention and changed-byte ranges. Pointer values and the embedded parameter-array pointer addresses are omitted; their unchanged identities are checked in-process. Parameter cells, labels, all five link slots, link counts and all capacities are separately exported. The `param` field's retention check covers all MAX_PARAMS entries. Observation projection covers every field of every allocated slot, including the unused tail. Nested zero-only pointer containers stay zero and are never dereferenced. The source object and all source observations have explicit unchanged checks.

Sparse byte representation is lossless for the initialized field storage on this host: omitted bytes are zero, pairs are `[offset, contiguous_nonzero_hex]`. Changed-byte ranges are half-open and describe differing representations, **not proof of every store**. Identical-value stores cannot be detected this way. The retained-field checks include full arrays, not just active counts. Struct padding is not interpreted as scientific data; field offsets, sizes and byte representations are host-layout evidence.

`copyPSR` copies name/binaryModel, fitMode (twice), nobs/nits, source nobs observation records, position/velocity, eclCoord, nJumps and jump slots **0 through nJumps inclusive**, FD slots **0 through destination's prior nfdJumps inclusive**, nFit/offset, selected timing controls, four clock/ephemeris strings and dm_series_type. It does not copy parameter arrays, nfdJumps, fdjumpIdx, jumpSAT, jumpScaled, acceleration, covariance ownership or the other fields. The four cases include destination FD count below/above source, zero count (still slot zero), and full declared observation capacity. `copyParam` copies eight cell arrays and then aSize, leaving pointers, link counts/arrays and capacity tail unchanged. Overlapping strcpy and undersized allocations are never invoked.

## Links, diagnostics and observation classes

The five links are DAOP<-PBDOT (PB, PMRA/PMDEC, binary64 SPEED_LIGHT/SECDAY/MASYR2RADS/PCM with the source expression order); KIN<-STIG (`asin(2s/(1+s*s))*180/M_PI`); SINI<-KIN (`sin(kin/180*M_PI)`); DSHK<-PX (`1/px`); DMMODEL<-DM (cell zero). Every target is also tested unlinked and linked to an unrecognized ID; those return the target's requested array cell. Dependencies themselves carry another link, demonstrating direct stored-value lookup rather than recursion. A duplicate two-link count prints the exact source message and exits 1 before an end event; no result is synthesized.

Every formatter call is classified `host_abi_formatter`: raw source unconditionally calls va_end on uninitialized oargs and ends the caller's args before the wrapper ends it again. This host returns zero; it is neither snprintf length semantics nor a portable successful-result contract. Formats are developer-authored, bounded, nonempty, and use type-matched initialized arguments (unsigned integer arguments are representable in the corresponding signed va_arg type). `%s`/`%c` outputs are nonempty. No arbitrary format is interpreted by the harness.

Diagnostics retain the raw TKlog implementation and process globals. Types 1 and 3 share a 50-key case-insensitive history. noWarnings=2 suppresses them without recording a key; negative noWarnings uses direct printf and bypasses history/log counters; other nonnegative settings share suppression behavior. A first duplicate causes one DUP1 warning even for a previously minor/quiet key. Quiet suppresses logmsg printing, not warning/error output or key recording; debug has no effect on displayMsg. Other types use logerr regardless of noWarnings. At 50 keys every new key logs `Too many warnings!`; existing keys still follow duplicate rules. The `warningNum>MAX_MSG` branch is unreachable from declared state.

TKlog counters count all emitted warning/error calls, but only the first 30 strings are stored in 360-byte arrays. `logerr_check` prints summaries and omitted counts, returns the old error count, and resets counters without erasing stored strings or displayMsg history. Both storage and output truncation are observed; path length consumes part of the output buffer, so normalization cannot restore truncated content. Selected dependency coverage is `_TKchklog`, `logerr_check`, logmsg/logall, logwarn/logerr, TK_STORE_WARNING/TK_STORE_ERROR, and non-TTY color stripping. TTY behavior, direct logdbg/logtchk and general logging-subsystem acceptance are deferred.

Colored log formats begin with ESC. The stripping loop in TKlog.C forms `buffer-1` with `--ptr` before immediately incrementing it; it does not dereference the before-start pointer in these selected calls. This is still outside portable pointer arithmetic, so full diagnostic fixtures are conservatively labeled `host_diagnostic`. No source overread/overflow is used to make a diagnostic golden. Direct negative-noWarnings and minor-only calls are covered inside this conservative full-case label.
