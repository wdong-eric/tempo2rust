## Canonical storage and initialization

Preserve all **166 enum entries**, including `param_LAST` and the three following virtual parameters, and all **2,000 allocated slots / 9,616 cells**. Unnamed slots and blank labels remain present. `param_LAST` is a marker, not an allocation size. Preserve source capacities independently of logical `aSize`; a copy may reduce the logical size without deleting the retained backing cells.

Keep source `int` semantics for `aSize`, `fitFlag`, `paramSet`, link indices and counts. Do not replace the internal flags with bool/u8 or infer source indices from alphabetically sorted names. A table keyed by PAR spelling is a view, not the registry. Preserve blank, overwritten and unusual labels, including `param_daop` being overwritten with `IPERHARM` while `param_iperharm` remains blank. Explain that source defect beside the corresponding initialization.

Allocation sets `val`, `err`, fit/set flags and link counts to zero and creates zeroed label buffers. `initialiseOne` then assigns parameter labels in source order. Use owned initialized Rust storage without fabricating upstream values: `prefit`, `prefitErr` and inactive link entries are explicitly unwritten until assigned, for example with `Option`. A read requiring an unwritten value returns a named safe-boundary error. Do not use zero, NaN, an allocator pattern or K's caller sentinels as a default. K's initialized versus caller-seeded projections must remain separate. Reuse or replacement drops Rust-owned allocations normally; no C allocation leak or undefined lifetime is emulated.

Keep Rug at **128 significant bits**. Internal numeric storage can use the existing Rug representation directly, including nonfinite values when explicitly supplied by a controlled caller; do not silently change the public finite `Scalar` construction contract. This stage performs assignments/copies, not new numerical algorithms or token conversion. Preserve precision and signed zero when cloning a value. No new dependency, C numeric ABI, rounding mode or arithmetic fusion is authorized.

## copyParam and safe access

Copy each source cell in this order: label, shortlabel, val, err, fitFlag, paramSet, prefit, prefitErr; assign destination `aSize` last. The source remains unchanged. Destination links/counts, backing ownership and cells beyond the copied extent remain unchanged. C-string copy writes through its terminating NUL and retains later destination bytes; replacing the entire label buffer or trimming it changes that behavior. Preserve the zero-count case. A negative signed `aSize` executes no loop and is assigned to the destination; this defined helper behavior must not acquire an automatic validation error.

Replace undefined source access with a contextual boundary at the first invalid operation: missing source/destination cell, unwritten value being read, missing string terminator, insufficient label storage or overlapping string buffers. Retain earlier defined writes; do not roll back, grow/truncate the destination to hide the error, publish a successful value, or execute an invalid native probe. Safe Rust ownership should make aliasing impossible where practical. If a boundary occurs during a multi-step mutation, mark that affected destination unavailable for further scientific use; expose its defined prefix only to diagnostics/tests. A fresh explicit caller can create another object. There is no source terminal exit in the selected copy helper to reproduce with process exit.

Native pointer addresses and C/MPFR object layouts are not equality targets. Ownership retention, source immutability, full initialized label bytes, logical/backing extents, integer fields and initialized numeric values are targets. Rust `Clone` for an entire owned input remains distinct from source `copyParam`; do not substitute one for the other.
