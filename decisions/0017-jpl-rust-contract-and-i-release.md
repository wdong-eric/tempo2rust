## Retain C stdio, transfer the JPL logic

This refines decision 0011's candidate removal of the entire reader boundary. H and a separate central probe established that stdio buffering affects observable source behavior: with 137 bytes left on disk in a neighboring record, `fread(size=8,count=825)` returns 85 complete items, or 680 bytes. The source then returns statuses `0,-2,0`, retaining the partial cache on retry. An immutable snapshot or an ordinary Rust `File`/`BufReader` implementation would remove this observed path.

The [central experiment](/Users/Eric.Dong/Downloads/tempo2rust/decisions/evidence/jpl-stdio-probe.py) opens once, reads the same descriptor to model a provenance pass, rewinds, and transfers it to `fdopen`. All 55 H scenarios / 1,443 events match both canonical `fopen` and the recorded reference exactly on macOS arm64. [Its recorded result](/Users/Eric.Dong/Downloads/tempo2rust/decisions/evidence/jpl-stdio-probe.json) pins the experiment, harness, fixture runner, manifests and source hashes. Reproduce with `python3 decisions/evidence/jpl-stdio-probe.py`; all generated sources/inputs stay in temporary storage. This is evidence for the I/O architecture, not a Rust implementation, concurrency guarantee or portable numerical proof.

Adopt one production stream path:

1. Open an owned Rust `File` once. When runtime provenance is needed, hash/read that same open file and seek it to the source's initial position before creating the C stream. Never validate one byte array and reopen its path. The hash records the bytes observed during that pass; it does not promise an immutable inode or a consistent snapshot during concurrent writes.
2. Transfer descriptor ownership to `fdopen` only after success. On failure, the Rust `File` still closes its descriptor. On success, the Rust file relinquishes ownership and exactly one stream owner calls `fclose`. No duplicate owner, escaped `FILE*`, `unsafe impl Send/Sync`, cloneable stream, or parallel access to its position/cache.
3. Retain `fread` item-size/count semantics and `fseek` call order/status. Bound every native write by an initialized mutable byte slice with a checked size product. Do not substitute `read_exact`, retry a short read, clear errors automatically, add read-ahead, hash through the stream after initialization, or seek merely to normalize its state. Partial bytes and bytes retained from earlier cache contents remain visible.
4. Decode header and cache bytes into Rust values with explicit byte order. All JPL arithmetic, indexing, record/cache bookkeeping, constant handling and interpolation execute in safe Rust. No packed typed pointer dereferences and no retained JPL C algorithm.

The unavoidable unsafe sites are confined to the foreign declarations and bounded stream calls. Each needs an adjacent necessity statement and ownership, buffer-size, aliasing and lifetime invariants. Count and review the final sites; do not promise zero unsafe or preserve a count by making a larger block. SOFA's existing two sites remain a separately documented retained dependency. No new numerical backend or general interchangeable-I/O framework is needed. A private test-only fault boundary is allowed to exercise H's injected seek/read/allocation failures.

## Preserve the source's defined decisions

The detailed source map and ordered H cases are requirements, not examples from which to infer a cleaner model. In particular:

- Preserve title-based version parsing, the strict `ncon > 65536` byte-order trigger, pre-430 and extended header routes, the 400-name scan, optional pointer clearing, signed integer getter interpretation, and native binary64 fields. Do not add finite/AU/grid restrictions to the low-level reader where the source has defined behavior. A guard needed for an undefined conversion or invalid access belongs at that operation and must have an explicit disposition.
- Preserve initializer status ordering and the distinction between a null handle and a live handle with status `-7` or `-8` after optional constant reads. Preserve the sequential process-global error query: startup `-9`, reset on initialization, unchanged by close. Safe storage may remove a C data race; do not silently turn the error into a per-handle register or claim concurrency equivalence.
- Preserve `jpl_get_constant`'s ignored seek returns and acceptance of any positive name/value byte count. Preserve caller name suffixes/terminators, the initially zero value bytes and byte swapping after a positive partial value read. Defined positive short reads are not all-or-nothing failures.
- Preserve early target-equals-centre success, optional targets' centre bypass, any-nonzero velocity semantics, source body/list/IPT indices, Earth/Moon special handling, SSB/EMB mapping, optional output lengths and shared destination overwrite order. Preserve AU, AU/day, AU/day² and native optional-quantity units. Pass the same binary64 JD argument; do not invent a time-scale conversion.
- Preserve the previous-record selection at an exact nonzero record boundary, the intervals `1,2,4,8` loop, untouched outputs for unvisited requests, Sun epoch caching and interpolation demand caches. Keep reverse coefficient accumulation, recurrence grouping, velocity and acceleration factors and source expression order. Do not replace the recurrence, introduce compensated sums or explicitly fuse operations without source evidence and central review.
- Restore the canonical **cache-before-read** behavior. Commit the record number before seeking; keep partial/old bytes and skip swapping on failed reads; the same-record retry skips I/O. Preserve recovery after another record is read. This deliberately removes the previous native cache correction recorded by F's B03; the corrected-reader expectation must leave active tests.
- Preserve open-file lifetime: path replacement retains the old opened object, in-place overwrite can affect uncached reads, a cached record remains cached, and reopen sees the new path. Keep the recorded stdio behavior on the declared host.
- Preserve defined NaN and signed-infinity classes at the low-level API. A successful source status with nonfinite arithmetic is not a finite zero or a newly invented I/O error. Existing high-level timing rejection of invalid/nonfinite results remains an explicitly recorded adapter; this stage does not close all of `readEphemeris.C`'s behavior differences.

Use source-width integer arithmetic where it is defined, including unsigned wrapping at the actual source expression boundaries. Rust's saturating float-to-integer casts must not silently define a C undefined conversion. Check conversion/index/allocation bounds before use; report a distinct boundary error rather than a fabricated canonical status or success vector.
