## Process state and library boundaries

The production clock index, loaded tables, cached sequences and diagnostic history have **process lifetime**. A new `RuntimeContext`, changed runtime root, changed extra directory, or changed file does not clear them. Preserve the separate initialization points of the clock and observatory databases. The first call that actually needs each database establishes it; a normalized clock identity must still return before clock indexing. Preserve table lazy loading independently of header indexing. Use safe synchronized ownership and borrowed internal state; acquire state at the outer entry and avoid nested-lock recursion. Serializing Rust calls is an explicit race-safety adapter, not a claim to reproduce C data races.

There is one production source path. Do not keep a per-context clock mode or a reset switch to satisfy old tests. A fresh reference experiment uses a fresh process. Test-only entry points can expose initialized state and direct helpers without making caches/reset controls public. Source globals such as the extra clock path and warning/debug flags may be supplied through a small internal configuration surface; do not invent new environment-variable spellings or CLI options. Existing `RuntimeContext::new(root)` remains usable and supplies the runtime root at use.

Normal source fallbacks continue normally, including successful zero correction after exhausted lookup. They must not become resource errors. At a source `exit(1)`, the library returns a distinct contextual terminal-source error and retains the defined diagnostic/state prefix. The affected shared source session becomes terminal: subsequent clock operations report that state until a fresh process starts. There is no canonical C continuation after exit, and no automatic rollback/reset/retry is introduced. A standalone table owner that reaches a terminal load failure is likewise no longer usable. Safe-boundary failures that replace undefined source access retain the defined prefix and invalidate the affected operation/owner rather than publish a value. This is an explicit Rust host-lifetime adapter; it does not call `exit` inside the library.

These decisions supersede the earlier touched-clock expectations that a new context reloads the database, a loaded file's removal must fail, or malformed/decreasing rows and exhausted fallback must reject. Replace those active expectations with source-faithful process/cache tests. Keep historical reports unchanged and retain unrelated JPL/IFTE/EOP recovery requirements. The CLI still reports failure without publishing a partial timing JSON document.

## Explicit safe boundaries

The following are source-based decisions, not claims that J executed its withheld cases. Do not run the withheld native invalid-access/cycle experiments through an alternate route.

| Source operation | Rust disposition |
| --- | --- |
| Empty table value/start/end access | Return `table_sample_storage` before indexing empty storage; no endpoint or zero value is invented. |
| Singleton exact/NaN query reaching `isamp-1` | Preserve earlier endpoint tests, then return `table_bracket_storage` at the invalid bracket. Valid singleton endpoint proxies remain valid. |
| Header `fgets(...,1024)` into `header_line[256]` | Read safely and return `table_header_storage` before the source's first overflowing write. Up to 255 stored input bytes plus NUL fit; use bytes actually read, not visible C-string length, to decide. Do not reinterpret an overflow as a longer supported header. |
| Basename copy or another selected fixed-buffer copy that exceeds its source destination | Return a named string-storage boundary at that copy. Preserve long full paths when their actual source operations are bounded. Do not put one arbitrary path/name cap on all entry points. |

| Invalid indices, consumed unwritten dependency fields, signed overflow or out-of-range integer conversion | Stop at the actual undefined operation with a named boundary and defined prefix. Do not infer whole-input rejection where an earlier source branch succeeds. |

Use initialized owned storage, explicit absence and safe slices. Controlled test sentinels are caller inputs, not claimed source defaults. Preserve source-width arithmetic where defined. A source capacity check that returns false/zero is still that normal outcome, distinct from these new boundary errors. Natural uninitialized diagnostic/output storage has no numerical golden.
