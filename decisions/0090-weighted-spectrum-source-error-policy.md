## Source evidence and statistical scope

At the pin, `TKspectrum.C:113` sorts x/y; the averaging block explicitly does not use error bars. The driver transforms x/y, uses a fixed 4096-point spline grid, smooths and differences y, then passes unchanged `e` to `TK_weightLS` or `TK_fitSinusoids`. See the driver through line 392 and helpers `TKfirstDifference` (428), `TK_fitSinusoids` (446), `TK_weightLS` (465), `TKaveragePts` (559), `TKhann` (677) and `TKcmonot` (707). The `spectrum` plugin and `choleskyRoutines.C` callers establish that weighted transformed/differenced paths are used; those callers provide context without adding plugin migration scope.

A central native trace instruments only the two weighted dispatch sites, records their actual x/y/e arguments and returns before the estimator. It executes the pinned transforms on eight sorted, distinct-error observations. Direct and first-difference cases each dispatch eight rows with the original errors. Averaging dispatches four rows with the first four errors `[1, 3, 2, 4]` to each weighted estimator. Width-three Hann dispatches six rows with the first six errors. These observations establish the driver contract, not spectrum correctness. The unsafe small-input spline path was inspected but was not executed.

Even under independent input errors, averaging generally changes variances; smoothing and differencing can introduce correlations. The monotone spline's slopes also depend on the data, so a universal fixed linear propagation matrix is not assumed. The existing source centering and estimator conventions remain intact. The warning reports this statistical limitation without claiming every source use case has an independently established noise model.
