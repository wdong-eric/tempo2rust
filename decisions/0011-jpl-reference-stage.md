## Purpose and source boundary

The next candidate implementation replaces the retained JPL C reader with safe Rust while preserving its calculations and deterministic defects. This would reconcile F's B03 cache difference and remove the six unsafe Rust sites associated with the reader (one foreign declaration and five call blocks at the audited baseline). SOFA remains a separately identified retained numerical dependency. No milestone or full-core completion follows merely from removing these sites.

F's U1 finding also matters: the current wrapper validates bytes supplied to `JplEphemeris::open`, then C reopens the path. The comments' claimed native bounds depend on the file still containing those bytes; the API does not enforce that condition. A Rust implementation must read and validate the state it actually consumes and use safe ownership/indexing. This is a Rust boundary obligation, not permission to correct a defined TEMPO2 calculation or cache result. Resource lifetime and mutation semantics must be established from source before choosing file-backed or snapshot storage.

F's U2 finding concerns the generic native getter: the packed structure places AU at byte offset 28, while `jpl_get_double` dereferences a cast `double*` requiring eight-byte alignment on the audited host. The layout probe establishes a portability gap, not a crash or a portable numerical result for undefined access. H must record the field layout and getter contract separately from host observations. A later safe Rust port will preserve defined field values and observable getter selection without reproducing an invalid typed-pointer access; central review will record that boundary disposition explicitly.

The canonical target is `tempo2/jpleph.c`, `jpleph.h` and `jpl_int.h` at `fda6ad4a9753ad7dc5d291406f2f310a9161423f`. Inspect every implemented entry point and helper, not only the currently used DE405 calls. This includes initialization/error state, getters/constants, `jpl_state`, `jpl_pleph`, interpolation and derivative caches, byte order and cleanup. The header declares `make_sub_ephem`, but no implementation was found in this pinned checkout; inventory that distinction rather than inventing behavior. Keep the raw `jpl_get_pvsun` layout macro separate from the mathematical Sun state it exposes.

At [jpleph.c:594](/Users/Eric.Dong/Downloads/tempo2rust/tempo2/jpleph.c:594), the source advances `curr_cache_loc` before seeking/reading and returns before byte swapping on a short read. The later request can reuse a partially overwritten buffer. Preserve this sequence, including its byte-order consequences. F reproduced statuses `0,-2,0,0` for canonical code versus `0,-2,-2,0` for the retained corrected reader. Status equality alone does not prove equality of the subsequent defined numerical outputs.

[jpl_pleph](/Users/Eric.Dong/Downloads/tempo2rust/tempo2/jpleph.c:135) continues after a failed `jpl_state` call and can use uninitialized local arrays. A nonzero status is observable; those uninitialized array values are not portable numerical goldens. Distinguish that case from an explicitly initialized caller array passed to `jpl_state`, a previously populated coefficient cache, or a later successful call using stale data. Also distinguish the canonical initializer's unwritten fields from deliberately controlled kernel input state. Do not add an initializer fix to the canonical build or silently sanitize its output.

## Required evidence

1. Pin and hash the unmodified canonical source and any observational harness. Build a standalone reference without depending on the corrected Rust copy. Reuse F's cache reproducer as prior evidence, then extend it without editing F's files. Record compiler/platform/flags and function/type/units correspondence for each harness file.
2. Exercise the available real DE405 resource and declared synthetic binary layouts. Cover both byte orders, pre-430 and extended-header branches, absent/present optional quantities, constant-name/count handling, header/title decisions, and getter field offsets/types/alignment. Synthetic files test the encoding and algorithm; do not describe them as astronomical ephemerides. Record all field values and coefficient construction. Inventory branches not safely or practically exercised.
3. Probe ordinary target/centre pairs, target-equals-centre ordering, invalid indices, velocity on/off, direct `jpl_state` list/barycentric modes, optional quantities and Sun position/velocity/acceleration. Cover exact record/subinterval endpoints, adjacent binary64 epochs, repeated epochs, forward/backward queries and changing derivative/interval demands. Preserve source component counts, overwritten/untouched output slots, arithmetic order, AU/day conventions and mixed index schemes.
4. Probe initialization failures, range/seek/read statuses and ordered failure/recovery sequences. Include the original truncated-DE405 sequence in both native API layers, record defined cache bytes and post-failure mutations, and compare subsequent defined results. Use initialized sentinels for caller-owned outputs, separating untouched slots from source-computed values. Isolate assertions/exits/invalid accesses; report the last defined stage rather than manufacturing a successful solution.
5. Establish file lifetime behavior: replacement versus mutation of an already-open file, partial reads, cached versus uncached records, and successful recovery. Record the actual file/handle setup and all changes in the case. This evidence informs a safe Rust implementation's owned file/reader state; an immutable snapshot must not silently remove a source-observable deterministic mutation path.
6. Deliver round-trip decimal outputs, binary64 bits where needed for signed zero or byte-state interpretation, exact statuses/nonfinite classifications, input/source/resource hashes, a coverage manifest, and a reproducible exporter/runner. Regeneration and meaningful mutations must detect wrong indices/units, dropped or reordered sequence steps, altered cache transitions, wrong component counts and changed result classes.

Report actual numerical scales and repeatability. H does not set Rust tolerances, accept a port, replace the reference with analytic expectations, or correct a source defect. Independent Chebyshev/derivative checks are useful diagnostics with their assumptions stated; disagreement with source remains recorded source behavior under decision 0008. All undefined-source and adapter dispositions remain explicit central review items.
